# T23 — возврат хоста из чаши и восстановление сейва ноутбука

30.10.2026. После T22 пользователь сообщил о бесконечной загрузке хоста при
возврате из чаши в Сон и невозможности войти на ноутбуке в скопированный сейв.

## Что установлено по прогону

`bloodborne_pc/out/coop-dev/runs/20261030-222801-t22-combat-latency/`:
host p46104 / guest p7616, mod/timeline/captures и VPS relay. Оба процесса были
закрыты до сбора; live dump состояния ожидаемых задач получить уже нельзя.

- Хост загрузил m29 в 22:31:14. Native summon начат в 22:32:18; гость не дошёл
  до mounted контекста чаши. В 22:32:44 relay получил send timeout WSA 10060;
  позже восстановился, но это не завершило загрузку.
- Native OnRoomTimeOut в 22:32:59 перевёл хоста 3→7 (leaving). В 22:33:24
  началась загрузка/OwnWorldStep `01941C20`. До конца лога 22:34:30 этот же шаг
  выполнялся 60 раз/с: current map m29, reload phase 4, без завершения входа в Сон.
  Это живой цикл load barrier, а не доказанный GPU TDR. В журнале нет готовности
  task+140/+148 и флагов 1521/15A3; конкретная незавершённая задача неизвестна.
- В журнале хоста отсутствует suspension persistence при переходе в state 7.
  Код обрабатывал BBSC departure/quit, но не любой native вход в leaving.
  Нельзя утверждать, что найден единственный источник зависания: сам native
  barrier допускает и ожидание асинхронной задачи. Исправлен обнаруженный пробел,
  для оставшегося случая добавлены поля барьера.
- Native bbnet-журнал в этом прогоне снова отсутствует. Боевой тест T22 не
  состоялся; задержку урона/доставку из этих логов не объявлять установленными.

## Исправление lifecycle

`ReleaseBbscNativeLeavingSession` разрешает штатное завершение только при уже
выбранном игрой состоянии 7: один раз снимает persistence через существующий
SuspendBbscPersistenceOnce, отменяет ожидающий reinsert существующим механизмом.
Не вызывает дополнительный Stop/Leave, не меняет адрес загрузки/сейв/HP и не
сбрасывает задачи вручную. States 3/4/6 и обычный кооперативный follow сохраняются.

Вызов есть и в обычном game tick, и в OwnWorldStep, который продолжает работать,
когда game tick приостановлен загрузкой. Сайт закреплён как functional, поэтому
Research OFF не отключает этот путь. Capture пишет настоящий session state,
requested map, loading/own-world/1521/15A3 и состояния task+140/+148.
