**PT-5** (руна «Нечистота» не доходит до гостей, а хосту выдаётся много раз на загрузках).

Статусы: **CONF** — подтверждено логом или кодом/данными игры, **PLAUS** — правдоподобно, нужна проверка в игре.

## 3. Причины

### PT-5, хост: повторная выдача «Нечистоты» — CONF
1. Флаг 6676 входит в список NPC-флагов, которые «каждый игрок держит своими» (`efdb9bc:5375`).
2. Ванильная награда ставит флаг получения **внутри** выдачи `0x017D89F0`, а не через SetFlag `0x013CFCC0`. Поэтому `NoteBbscNpcOwnFlag` его не видит.
3. `RevertBbscNpcOwnFlags` на следующем тике возвращает 6676 в «своё» значение 0 (`efdb9bc:5515`), как будто его прислал другой игрок.
4. На следующей загрузке m27 событие 12700906 видит 6676=0 и 72700321=1 и выдаёт руну снова. То же для Посоха Лиги (6678).

Лог хоста `runs/20261027-test-collect/pc/bbsc-logs/bbsc-mod-20261027-211401-27712.log:25867-25870`:
```
[22:39:20.240] BBSC research: flag 72700321 = 1 (caller 0x2043f5c, session state 3 ...)
[22:39:20.241] BBSC pickup: lot given to the player (session state 3)
[22:39:20.241] BBSC own NPC quests: flag 6676 came in as 1 from the other player - ours (0) put back
```

### PT-5, гость: «Нечистота» не доходит
* Подарок — «только за свой разговор» (решение пользователя: так и оставлено). Если с Валтром говорил только хост, гостю руна не положена.
* Если говорил гость: самоцвет/руна шёл в `bbsc_home_awards` — в памяти, не больше 64 штук. Лишнее молча отбрасывалось (`efdb9bc:11161`), а дропы самоцветов с врагов быстро заполняют список. На каждой загрузке событие у гостя повторялось (тот же откат 6676 охраной), и в очередь попадали дубли. PLAUS (логов гостя с 43120 нет).

### PT-1: инструмент «окно было, предмета нет»
Разбор `eboot.elf` (objdump):
* Выдача `0x017D89F0` кладёт предмет в инвентарь **локального** игрока (`[[0x0553B130]+8]+0x328`, add `0x014CDA70` / `0x014D97F0`). Проверки типа игрока там нет. CONF.
* Окно `0x016D8850` ставится в очередь **только после успешного add** (`0x017D924C: test ebx,ebx / je 0x017D9270`). Значит, «окно было» = предмет в мире хоста **был добавлен**. CONF.
* Следовательно, предмет пропал **после**, на дороге домой. Пока гость в чужом мире, его сейв — снимок своего мира (`global+0x1592 == 0`, `efdb9bc:5204`); при возвращении домой персонаж восстанавливается из него. Это согласуется с тестом 20.10 (Значок охотника с мечом «положен», а дома его нет — ради этого и добавили `TickBbscBossGoodsCheck`). PLAUS: подтвердить строкой `K2-lost-on-trip-home` в тесте.
* Подбор шёл мимо любой сверки, а флаг в `guest-items` делал предмет «взятым» для этого персонажа навсегда → в своём мире его тоже не взять → софтлок рун.

### Общие слабые места
* Шесть путей и два списка «выдать дома» в памяти, без единой записи «что положено» и без сверки с инвентарём.
* Награда `0x017DDC50` у гостя вне своего мира смотрит на аргумент `forced` (`0x017DDCD9…0x017DDD3E`). BBSC везде передаёт 0.

## 4. Что изменено

**Единый журнал предметов** — `bloodborne_re.cpp:11284` («The item ledger»). Он свой у каждого персонажа и лежит на диске: `<bbsc>\item-ledger\ledger-<user>-<slot>.bin`.

| Что | Где (стало) |
|---|---|
| Запись «выдано в мире хоста»: окно ванильной выдачи (возврат `0x017D934D`/`0x017D94CC`) + явные записи BBSC (дроп, босс, ключ, разговор) | `NoteBbscLedgerWindow` :11707, `NoteBbscLedgerGiven` |
| Контекст выдачи: награда (лот, флаг) / подбор (лот по флагу kind 5 из `CaptureBbscGuestLoot`) | `BeginBbscLedgerAward`, `BeginBbscLedgerPickup`, `NoteBbscLedgerPickupFlag` |
| Сверка через 1,5 с: предмета нет ни в сумке, ни в хранилище → `CHECK FAIL K2-window-no-item`, предмет становится «положен» | `CheckBbscLedgerGiven` :11863 |
| Дома (5 с после загрузки): пересчёт; меньше, чем было в мире хоста → `CHECK FAIL K2-lost-on-trip-home`, возвращается разница (не больше, чем дала поездка) | `ReconcileBbscLedgerAtHome` :12067 |
| «Положено»: окно разговора без add, награда, которую мир хоста не дал, списки старого журнала → выдача дома, до 3 попыток | `GiveBbscLedgerOwed`, `NoteBbscLedgerOwed` |
| Ретро-починка (решение пользователя: ключевые и уникальные): ключи, инструменты, значки, чаши из `guest-items`, которых нет ни в сумке, ни в хранилище → выдать один раз (`CHECK FAIL K2-retro`) | `RetroBbscLedger` :11986 |
| **PT-5 фикс:** флаги получения своей награды считаются своими (охрана NPC-флагов не откатывает) | `RevertBbscNpcOwnFlags` :5501, `BbscLedgerOwnAwardFlag` |
| **K3 защита:** повторная награда одноразового лота, который у персонажа уже есть → пропуск, флаги ставятся, `CHECK FAIL K3-repeat` (только для уникальных предметов, не в Чашах) | `SkipBbscRepeatedLot` :11754 |
| Самоцветы/руны гостю **сразу** в мире хоста (решение пользователя): лот с самоцветом идёт через ванильную награду; если надёжный лот ничего не дал → `CHECK FAIL K2-award-nothing` и запасной путь BBSC | `BbscGuestAwardHook` :12206, `FinishBbscLedgerContext` :11843, `TickBbscGuestDrops` :12277 |

Удалено: `bbsc_home_awards` (лимит 64), `GiveBbscHomeAwards`, `bbsc_talk_items_meant/added`, `GiveBbscTalkItemsAtHome`, `TickBbscBossGoodsCheck`.
Журнал поездки `journal-*.bin` теперь **v2** (только флаги разговоров). Файл v1 при чтении переносит свои списки в журнал предметов как «положено» и сразу перезаписывается как v2.
Обход PT-1 (инструменты как общие ключи) **оставлен**: у друзей 27.10 `guest-items` мог не записаться на диск (LA-1), и тогда ретро-починке не на что опереться.

## 5. Затронутые предметы
* Всё, что гость получает в мире хоста: подбор, награды, дропы, боссы, разговоры, общие ключи.
* Ретро-починка: 4000–4021 (кроме 4014 Череп Лоренса и 4017 Подвеска), 4102–4105, 4110–4120, 6100–6539.
* K3/PT-5: лоты 43120 «Нечистота» (6676) и 43130 «Посох Лиги» (6678); блокировка — любые одноразовые лоты с уникальным предметом.

Известные ограничения:
* Сейв, где хост уже получил руну по старой сборке, может получить **ещё одну** при первой загрузке Запретного леса: журнал ещё не знает лот 43120, а 6676 сохранён как 0. После этого флаг держится.
* Количество самоцветов/рун не проверяется (у каждого свой экземпляр): для них только лог.
* NG+: повтор одноразовой руны, которая уже есть, будет пропущен (в ванили выдалась бы вторая).

## 6. Чек-лист теста в игре (хост = ПК testHost, гость = ноут test)

Подготовка: `coopdev build mod` → `deploy mod all` → `save snap pc` / `save snap laptop`. Логи: `%LOCALAPPDATA%\bbport-coop\BBSC-0.0.1-BBport\bbsc\logs\bbsc-mod-*.log`.

1. **Подбор (PT-1)**. Гость входит к хосту и подбирает 1–2 предмета с земли (лучше ключевой, если есть).
   Ждём: `BBSC ledger: pickup 0x4000…. x1 given in the host's world (lot …)`; **нет** `K2-window-no-item`.
2. **Дроп и самоцвет**. Гость убивает 2–3 врагов.
   Ждём: `ledger: enemy drop …` при выпадении; для самоцвета — `guest award: item lot … (blood gem / rune) … the game's award runs`; **нет** `K2-award-nothing`.
3. **Домой**. Гость выходит из сессии в свой мир и стоит 10 с.
   Ждём одно из двух: `BBSC CHECK OK K2-trip-home` (ничего не пропало) или `CHECK FAIL K2-lost-on-trip-home: … given back` (поездка забрала, предметы вернули). **В игре проверить, что подобранное лежит в инвентаре.**
4. **Повторный вход и снова домой**. Предметы не дублируются: в логе нет второго `given back` для тех же кодов.
5. **Хост, «Нечистота» (PT-5)** — на сейве, где хост уже говорил с Валтром. Хост дважды загружается в Запретный лес (лампа/смерть).
   Ждём: максимум одну выдачу и строку `own NPC quests: flag 6676 was set by our own item award - ours now (not put back)`; при следующей загрузке руна не приходит (или `CHECK FAIL K3-repeat … skipped`). В игре — число рун «Нечистота» не растёт.
6. **Ретро** (на сейве гостя, где инструмент «пропал»): дома в логе `CHECK FAIL K2-retro: goods 4104 … given now` один раз; при следующем запуске повтора нет.

Что искать:
```
grep -h "BBSC CHECK FAIL\|BBSC CHECK OK\|BBSC ledger" bbsc-mod-*.log
```
Любой `CHECK FAIL` с классом `K2-window-no-item`, `K2-award-nothing`, `K2-owed-not-given` или `K3-repeat` — прислать лог гостя и хоста. `K2-lost-on-trip-home` и `K2-retro` — ожидаемые срабатывания починки, но с ними тоже прислать лог: они подтверждают гипотезу об откате при возвращении домой.

## 7. Тест 2026-10-29 (прогон `runs/20261029-055243`, сборка 2d3e0c9)
* **PT-1 подтверждён.** Гость подобрал Белую ленту посланника (4903, goodsType 1). После выхода из сессии её не стало: `CHECK FAIL K2-lost-on-trip-home: 0x40001327 - 1 in the host's world, 0 at home - 1 given back`, журнал вернул ленту. Предмет пропал **в момент конца сессии** (6→0), ещё до какой-либо загрузки. Расходники — Осколок кровавика, пули, флаконы — не пропали. Значит, игра при конце коопа забирает у фантома именно ключевые предметы.
* **Двойной дроп с врагов.** Ртутные пули и Флаконы крови (единственные предметы с `isGuestDrop=1`) игра сама кладёт фантому на труп, а BBSC давал их ещё раз при убийстве. Исправлено: бросок BBSC эти предметы пропускает (`BbscGoodsIsGuestDrop`). Самоцвет или руну из лота врага BBSC бросает один раз и выдаёт сразу ванильной наградой только этой записи: веса остальных записей обнуляются на время вызова (`GiveBbscPickedLotEntry`). Прежний путь «ванильная награда всего лота» удалён: в 122 из 213 лотов врагов с самоцветами есть ещё флаконы или пули, и они бы задвоились.
* Не связано с журналом и заведено в BACKLOG: выход гостя Пустой печатью без загрузки домой (PT-9), хост после перезахода в точке старта игры (PT-10).
