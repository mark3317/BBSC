## Причина и исправление

В порте fast-sign повторяет create каждые 3 с только 5 раз, удерживая исходный ответ до 15 с.
После окна возвращается штатное расписание игры. В истории уже зафиксированы обновления знака раз в ~30 с,
несмотря на `--summon-interval 5`. Порядок звонков из сообщения согласуется с попаданием в fast-sign окно.
Точного сопоставленного свежего прогона двух машин для всех порядков пока нет; это объяснение по коду и истории,
а не измеренное доказательство устранения задержки в игре.

Дизассемблированием установленной CUSA03173 1.09 проверены реальные потребители:

- `[05540288]+18` — загруженные настройки; +89C create (01E89A57), +8A0 get (01E9597C / 01E97AF6).
- +8A4 — дополнительная защитная пауза get (01E98633 → manager+110), vanilla 60 с.
- `[0553B120]+C50`, +190 — кэш create-интервала, записывается при загрузке ss.info (01E89AAD).

Перед приватным summon-запросом DLL ставит эти три интервала и кэш create в 2 с, с проверками памяти/значений.
Заголовок `X-BBSC-Native-Summon-Polling: 1` выставляется только при успешной настройке.
Новый порт при таком заголовке сразу возвращает ответ create, без 15-секундного fast-sign удержания.
Старый мод сохраняет fast-sign; старый порт игнорирует заголовок. Для полного эффекта нужны обе новые части.
Публичные summon-запросы не меняются. Ответ с claim получает сама игра; фонового конкурирующего потребителя нет.

Это короткий штатный опрос в существующем асинхронном HTTP worker, не событийный брокер.
Событийный вариант возможен через расширение shadnet (подписки/пробуждение при create/request/delete,
отмена, TTL, фильтры пароля/типов/подземелья). В этой сборке протокол сервера не меняется.
Интервал 2 с не является обещанием полного входа за 2 с: остаются native join, signaling и загрузки.

## Лимит 5 минут

С первого наблюдения эффекта Beckoning/Hunt Bell 9000 в своём мире (state 0/3) идёт монотонный таймер.
На 300 с мод удаляет только эффект 9000 через штатное удаление SpEffect и показывает:
«Поиск окончен. Чтобы продолжить поиск, позвоните в колокол снова.»
Ни Blank, ни LeaveRoom, ни удаление членов группы не вызываются. Уже вошедшие гости должны остаться.
Отмена сбрасывает таймер, новый звонок получает новый срок; state 6 и чужой мир исключены.
Ошибка удаления повторяется следующим тиком, уведомление только после успеха. Существующий переключатель
Co-op texts управляет показом; событие окончания всегда попадает в timeline.

## Контроль после отдельного разрешения на деплой

Одна карта и разные карты: клиент первым (хост через 10 с), хост первым (клиент через 20–30 с),
одновременно, повтор после отмены/ухода. Замер от второго звонка до появления партнёра.
На хосте без клиента дождаться 5 мин: поиск выключен, один баннер, повторный звонок работает.
Повторить с уже подключённым гостем: по истечении срока гость остаётся. Проверить отмену около истечения срока.
