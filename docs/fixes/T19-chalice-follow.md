# T19 — следование в чашу без выхода из сессии

30.10.2026. По выбранной пользователем архитектуре алтари/ритуалы остаются личными,
гости временно используют подземелье хоста. Первый сценарий: уже соединённая группа
в Сне, хост создаёт чашу и входит; гости следуют без собственного ритуала и повторного
призыва. Текущие testHost/test, пользователь создаёт чашу сам, отката нет.

## Реализация

- Хост захватывает уже декодированные входные данные нативного stage loader:
  channel, layout map, 18 частей, тип, feature, виртуальную корневую карту.
  Передаётся описание без указателей, а не объект постоянного алтаря.
- SHAD `0x2B` v1, 136 байт: заголовок 8 + `Chalice::Mount` 128. Key остаётся
  каналом/хешем FormData; revision увеличивается при нативной загрузке хоста.
  Текущая resident map отделена от stage_map. Обработчик сети только кеширует пакет.
- WorldFlags m29 v4, 1050 байт: прежний пакет + Key 24 + revision 8. Все чанки
  одного снимка получают один захваченный контекст. Загрузка требует свежих,
  согласованных follow, описания загрузки и полного снимка той же revision/key.
  Перед записью проверяется именно копия применяемого снимка; свежесть нового
  кеша не разрешает применение старой копии. v3 принимается, но auto-entry не разрешает.
- Гость ставит временный контекст перед существующим RequestBbscSessionWarp.
  Hook подставляет его в регистры и стек native loader; после загрузки контекст
  отмечается mounted только при подтверждённой инъекции. Ни leave, ни disconnect,
  ни новый summon в этот путь не добавлены. При неудачном запросе staged-контекст
  откатывается к последнему mounted; чужие координаты до загрузки не применяются.
- Новая revision/key запускает загрузку даже при той же виртуальной карте.
  Обычная ходьба по resident parts одной revision не вызывает лишнюю загрузку
  и сохраняет захват личного лута. Возврат в Сон/свой мир очищает borrowed context.
- Защищены записи boolean и multi-bit в flags 9020..9026 и 94000000..94699999
  во время заимствования. Постоянные объекты/буферы алтаря не заменяются.
  T18 own-world journal, scoped loot и исключение m29 из Shared Progress сохранены.
  При отсутствии любого из трёх обязательных hooks автоматическая загрузка запрещена.

## Локальные доказательства native path

CUSA03173 v1.09, неизменённый локальный eboot.elf; файлы игры не редактировались.

- `01928680`: stage initializer читает выбранный ритуал через `01AB2A40`
  (channel), `01AB1DB0` (layout map), `01AB3070` (18 s32), `01AB31C0` (type).
- Hook `01928987`, checked bytes `44 89 6B 48 48 89 8B E0 00 00 00`:
  RBX=driver, RBP-78=parts, RCX=channel, RDX=layout, R8=type, R15=feature,
  R13=normalized stage map. Продолжение сохраняет эти значения в runtime loader.
- Без алтаря у гостя R13 может быть FFFFFFFF; driver+48 ещё содержит запрошенную
  m29 карту. Проверяются оба. Уже записанный global+0C также корректируется.
- Multi-bit writer `013D0060`, checked prologue `55 41 57 41 56 53`;
  boolean writer `013CFCC0` использует существующий функциональный SetFlag hook.
  Защита охватывает эти нативные API, а не является доказательством отсутствия
  любого возможного прямого writer в игре.

## Один игровой прогон

1. ПК хост/testHost, ноут гость/test. Соединиться обычным способом, оказаться
   вместе в Сне. У гостя чашу не создавать; по возможности запомнить его алтари.
2. Только хост создаёт/выбирает Птумеру и входит. Гость ждёт авто-follow,
   не выходит из группы и не звонит повторно. Сверить геометрию и видимость игроков.
3. Если вход успешен: короткая ходьба, предмет, возврат хоста в Сон и повторный
   вход; проверить следование и личные алтари гостя. Затем уже расширять маршрут.
4. При сбое записать момент/экран обоих; зависший процесс оставить для анализа.
   После успешного прогона закрыть игру, сообщить результат для сбора логов.
