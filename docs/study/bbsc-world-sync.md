## 1. Модель данных
- Все event-флаги — `SprjEventFlagMan` `[image+0x0553B100]` (`re:5187-5205`): группа = flag/1000, 125 байт,
  бит считается от старшего; std::map key→node (kind 1: индекс в +0x28, kind 2: указатель). Поиск группы —
  `BbscFlagGroupStorage` `re:5291` (повторяет lower_bound 0x013CFD80). SetFlag игры — 0x013CFCC0; BBSC пишет
  флаги через 0x0132E5A0 (`re:11423`, `re:12800`) или прямой записью байтов.
- Ключи групп блока карты AA/B: `kind*10000 + AA*100 + B*10 + 0..9` (`BbscWorldGroupKey` `re:5280`):
  kind 1 — события (боссы, двери, шорткаты, лампы, катсцены); kind 5 — подборы предметов; kind 6/7 — NPC/объекты.
  Глобальные (<100000: сюжет, квесты) world sync не пишет.
- Источник истины: мир хоста. Гость получает копию в свою живую таблицу; своё хранит в журналах (ниже).

## 3. Что остаётся у гостя своим (исключения при записи хостовых групп)
Порядок в `write_block` `re:5799-5827`: `KeepBbscOwnWorldGroup` → memcpy хоста → `KeepBbscGuestTalkBits` → `KeepBbscNpcOwnBits` → (Сон) мессенджеры.
- **Свои NPC-квесты** (2026-10-27, `re:5339-5571`): 788 флагов `BbscNpcQuestFlags`; `bbsc_npc_own` = своё значение,
  обновляется хуком SetFlag (`NoteBbscNpcOwnFlag`), всё чужое откатывается каждый тик и в начале event update (0x012ECDC0) / talk-step. Работает в состояниях 3/4/6, и у хоста тоже. `SHADPS4_BBSC_OWN_NPC_QUESTS=0` выключает.
- **Talk-driven events** (`re:12812-12984`): 507 пар event→flag; событие, чьи триггеры не «наши», при первом 2003 решается «не наше» на 2 с — все его SetFlag и выдачи пропускаются (`re:12992`).
- **Подарочные триггеры** `BbscGuestGiftTriggerFlags` (12 шт.) и всё из журнала разговоров (`re:12610-12634`).
- **Мессенджеры Сна**: группа 72101 целиком, 12101 биты 20-29, 12105 биты 50-69 (`re:5784-5798`).
- **Магазины Сна**: 70009 (продажи) + 130 unlock/met-флагов (`re:5956-6002`).

## Кандидаты в находки
- **WS-1 Чаши в shared progress.** Хост в чаше (область 29) шлёт снимок своего текущего блока (`re:5659-5662`, 29 исключена только из «других» блоков `re:5690`); `TickBbscSharedProgress` OR-ит kind 1 всех блоков, исключая лишь Сон (`re:11660-11683`). Id карт чаш общие для всех подземелий (`re:5266-5267`) → дома в чашу гостя с тем же id вливаются двери/боссы чужой чаши. Проверить: шлёт ли хост в чаше (IsUsablePackedMap) и какие флаги kind 1 у чаш.
- **WS-2 Журнал разговоров, talk-items и home awards — только в памяти** (`re:12601`, `re:12697-12698`, `re:11054`). Краш/выход гостем: own world и pending progress восстановятся из файлов, а map-флаги шага квеста и обещанные предметы/blood gems/руны — потеряны («полшага квеста» снова, глобальная часть при этом уже в сейве).
- **WS-3 Свои квесты и награды завязаны на Shared Progress.** `ApplyBbscTalkJournal`/`GiveBbscTalkItemsAtHome`/`GiveBbscHomeAwards` вызываются только из `re:11749`, `re:11796`, а оба пути выходят при `SHADPS4_BBSC_SHARED_PROGRESS=0` (`re:11618`, `re:11783`). С выключенным переключателем гость теряет квестовые map-флаги, предметы разговоров и home awards. CONFIRMED по вызовам (grep).
- **WS-4 Ключи/жетоны: устаревшее состояние и нет фильтров.** `bbsc_host_key_items` не сбрасывается вне сессии (`re:18221-18223` сбрасывает только `last_applied`) → при входе к новому хосту до 3 с выдаются ключи прошлого хоста. `OnBbscKeyItemsPacket` сам отправителя не проверяет (`re:18257`), но в мод-DLL фильтрует `Dispatch` (`from_our_host`, `emulator/mod/bbsc_relay.cpp:283-286,338-341`; подделка sender — см. SN-02); `TickBbscSharedKeyItems` не проверяет тип игрока (инвейдер в состоянии 6 тоже получит ключи), в отличие от `re:11630`. Выдача необратима (в инвентарь сейва).
- **WS-5 «Не наше» событие глушит ВСЕ его флаги.** Комментарий `re:12820-12821`: пропускаются NPC-квестовые флаги и награды; код `re:12992` пропускает любой SetFlag события. Если talk-driven событие ставит и kind 1/общие флаги (дверь, мировое событие), у второго игрока мир расходится. Нужен скан 507 событий на SetFlag вне `BbscNpcQuestFlags`.
- **WS-6 Неполная запись «всех областей» при быстрой загрузке.** Готовность проверяется только для блока назначения (`re:5746-5754`); другие области приходят по 4 блока/с (`re:5706`) и пишутся, только если уже есть (`re:5848-5856`, лог «no fresh host flags for other areas yet» `re:5887`). Гость, загрузившийся в первые секунды после входа, получит часть областей на своих флагах — исходный баг «Paarl/BSB убит сам» (`re:5250-5262`) может повториться. Также нет повторной записи областей, пришедших после загрузки.
- **WS-7 Один буфер сборки на версию** (`re:5583`, `re:18457-18463`): хост шлёт до 5 снимков подряд за тик; переупорядочение/потеря одного чанка сбрасывает сборку — блок пропадает до следующего круга. Зависит от транспорта (relay/UDP) — см. область 3.
- **WS-8 Противоречие о сейве гостя.** `re:5203-5204`, `re:5231`, `re:6705-6706`: «пока гость, сейв пишется из own-world snapshot (0x0156AA50)»; `re:6281`, `re:11487-11489`: «сейв берёт флаги из ЖИВОЙ таблицы (0x01399DE0)». От этого зависит, что лежит в сейве после краша гостем. Проверить по коду игры.
- **WS-9 OR kind 1 предполагает монотонность** (`re:11433-11444`, «only adds»). Если в kind 1 есть парные/переключаемые состояния (лифты, рычаги, «дверь открыта/закрыта», фазы событий) — OR даст несовместимую комбинацию в мире гостя. Нужен скан emevd на сбросы (SetFlag …, 0) kind 1.
- **WS-10 Первое наблюдение NPC-флага = «наше»** (`re:5510-5512`): если чужое значение попало в глобальную группу до первого тика сессии (game talk sync в состоянии 4), оно закрепится как своё. Низкий.
- **WS-11 Время «unknown» при раннем хосте**: хост без 9800-9802 → `-1` (`re:18343`), гость остаётся на своей ночи в мире хоста. Задокументировано, низкий.
- **WS-12 Сверка talk-items по type+id без количества** (`re:12758-12760`), а `added` ловит любой AddItem (подбор того же id) — недовыдача. Низкий.
