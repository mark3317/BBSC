# Область 3 — сессия и сеть (SN)

Источники: `emulator/src/core/bloodborne_re.cpp` (`re:`), `emulator/mod/*.cpp` (`relay:`, `channel:`, `http:`, `mod:`),
`server/gameserver/bbsc_gameserver.py` (`gs:`), `bbhost_service.py` (`bh:`), `bbport/bbport-1.7.2-bbsc.patch`.
Основа — заметки прошлого агента (scratch `sn/notes.md`, читал relay/channel/http целиком); проверено заново в эту
сессию: катсцены, Dispatch/SendFrame, relay-форвардинг сервера, follow, partner-gone. Не перепроверено: bbhost_service,
bbnet/shadnet, signaling в патче, bbsc_http (SN-03, 04, 09–12, 14 — «по заметкам»).

## 1. Состояния сессии
`GetSessionState()`: **3** хост, **4** гость входит (joining), **6** гость/инвейдер в чужом мире; тип игрока 1 = кооп-гость,
2 = инвейдер (`re:11630`). «Свой мир» = `global+0x1592 != 0`, идёт загрузка = `global+0x08 != 0`.

## 2. Жизненный цикл (по тикам)
Главный диспетчер: game-tick сайт в `re:17233-17355`, ~70 `TickBbsc*` по порядку (follow, world flags, life, session end,
spectate, rejoin, self-heal …). Ключевые этапы:
| Этап | Где | Суть |
|---|---|---|
| Призыв / вход | `re:4302-4700` (relay-сессии, join teleport) | хост и гость находят друг друга через relay (Placement/AimedPlacement), после загрузки — телепорт к хосту (`BbscJoinTeleportSettleMs`=2 с) |
| Следование (warp together) | хост `TickBbscFollowBroadcast` раз в 0.5 с `re:4717-4840`; гость `TickBbscFollowHost` `re:4927-5178` | гость грузится в карту хоста, если хост в другой карте >2.5 с и не «рядом» (120 м) или карта не загружена; ждёт флаги хоста ≤4 с; ≤3 попытки на карту, таймаут прибытия 90 с; в Сон хоста не идёт, пока у гостя не пройдено начало |
| Смерть / спектатор | `re:3934-4160`, `re:7194-8800` | life-пакеты 0.5 с; вайп → перезагрузка у лампы хоста; наблюдение за живым |
| Перезагрузка мира (rejoin v5/v8) | `re:3395-3935` | отложенная перезагрузка, reinsert задач, self-heal (4 с без партнёра) |
| Конец сессии | `re:9109-9545`, leave locks / stranded `re:9545-9760` | выход в меню — временно снимает persistence-патчи на 20 с; партнёр «пропал» — 180 с без единого удалённого персонажа |

## 3. Транспорт BBSC-пакетов (мод-DLL)
- Все BBSC-пакеты (`SHAD` + тип) уходят через `SendFrame` `relay:186-211`: конверт `SHAD 0x?? sender(own_id) session`;
  **TCP-relay на игровой сервер**, если подключён; иначе **UDP P2P-канал** `channel:305+` (дублирования нет).
  Очередь клиента 256 КБ (`relay:96`), при переполнении новые кадры молча отбрасываются (`relay:200-205`).
- `SessionKey` `relay:173-182`: хост = свой id, гость = id своего хоста.
- Приём `Dispatch` `relay:259-360`: пакеты «только от хоста» (follow, scale, progress, boss, key items, cutscene,
  world flags) принимаются только если `sender == session == GetBbscRelayHost()`; life — только своей сессии;
  Placement — от любого хоста (поиск знаков).
- Сервер `gs:1151-1216`: **по умолчанию каждый кадр уходит всем клиентам relay** (маршрутизация по сессии — опция
  `--relay-session-routing`, в репо нигде не включена). Очередь на клиента 512 КБ, переполнение = отключение клиента
  «too slow» (`gs:1047`, `gs:1247`). Аутентификации нет — `sender` в конверте берётся на веру.

## 4. Типы пакетов (из Dispatch)
Follow, Life, Scale, Pvp, Progress (0x26), HostBoss, KeyItems (0x29), Cutscene (0x28), Placement, AimedPlacement,
WorldFlags (`kSignalingBbscWorldFlagsType`), Peers (счётчик от сервера).

## Кандидаты в находки
- **SN-01 Катсцена хоста повторяется у гостя с сырыми указателями хоста.** `re:18095-18110`: `rcx` копируется байтами только
  если указывает в стек; иначе в пакет идёт сам указатель из памяти хоста, а `stack[0..2]` — сырые qword'ы стека хоста.
  Гость вызывает функцию запроса катсцены с ними `re:18300-18306`. Если это указатели — чтение мусора/краш у гостя.
  Дедуп только по последнему sequence `re:18128-18132`. CONFIRMED (код), последствия — гипотеза.
- **SN-02 Relay: глобальная рассылка и нет аутентификации.** `gs:1151-1216`: при выключенной маршрутизации (по умолчанию)
  каждый клиент получает трафик всех сессий сервера: world flags (до ~5 снимков × 5 чанков/с на хоста), cutscene, progress.
  Трафик растёт как N², медленный клиент вылетает по лимиту 512 КБ. Фильтр есть только на клиенте (`relay:283-286`),
  `sender` можно подделать → чужие world flags/ключи/катсцены «от твоего хоста». CONFIRMED (код).
- **SN-03 BBR1 register без авторизации** в `bh:757-770` (по заметкам) — перехват регистрации.
- **SN-04 Коллизии UserId:** `identity_for` на 9000 корзин `gs:156-167` против прицельного призыва по user id `http:726-746` (по заметкам).
- **SN-05 «Партнёр пропал» не срабатывает в группе 3+.** `re:9119-9125`: снятие патчей только когда нет НИ ОДНОГО удалённого
  персонажа 180 с. Упавший гость при живом втором гостей оставляет фантом; в доках указано 90 с (по заметкам).
- **SN-06 Начало игры у гостя блокирует Сон** `re:5109-5121`: хост ушёл в Сон, гость с непройденным началом не идёт следом
  и остаётся в мире хоста без хоста (stranded-логика `re:9698` — 15 с?). Нужна проверка, чем кончается.
- **SN-07 Follow сдаётся после 3 попыток** `re:4844`, `re:5095-5101`: пока хост не сменит карту, гость остаётся в старой.
- **SN-08 Следование без флагов хоста.** `re:5129-5139`: через 4 с без снимка гость грузится «with our own» флагами — это
  тот же сценарий, что убивал босса у гостя с выдачей эхо и чаши (`re:5257-5262`). Снимки теряются из-за SN-02/«too slow»,
  сброса очереди клиента `relay:200-205`, перехода на UDP (WS-7). Связано с WS-6/WS-7.
- **SN-09 P2P-канал выключается до конца запуска** после 10 неудачных OpenSocket `channel:260-264`.
- **SN-10 Liveness signaling не учитывает echo pong** (патч, np_signaling_state ~1235; по заметкам).
- **SN-11 Relay по умолчанию force=true** — весь трафик через VPS, peers/alias не истекают (p2p_relay 140-146, по заметкам).
- **SN-12 Блокирующий WinHTTP в HTTP-потоке игры** до ~4.5 с в `ClearStaleRecord` `http:349-370` (по заметкам).
- **SN-13 Запись байтов кода на лету** в `SetPersistentSessionPatches` (не атомарно, 5-байтовые патчи) `mod:661-688` — гипотеза.
- **SN-14 Self-heal перезапускает задачи, когда партнёр просто в другой карте?** `re:3866-3930` — гипотеза.
- **SN-15 Эмуляторная сборка: приём follow/flags от любого источника** (helpers 375-410) + StunEcho на любые 6 байт (по заметкам).
- **SN-16 Опция маршрутизации: устаревшая подсказка сессии для входящего гостя** `gs:1163-1200` (по заметкам).
- **SN-17 В моде `BbscReplayRoomMembers` — заглушка, возвращает 0** `mod:1010` → экспериментальный REINSERT в моде ничего не делает (по заметкам).
- **SN-18 `SendFrame` при отброшенном кадре возвращает число пиров** `relay:205` → вызывающий код (логи «sent to N peers»)
  не видит потерю. Низкий.
