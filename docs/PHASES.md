## Чаши: текущая реализация и следующий этап

T18: реализована первая часть идентичности (канал + хеш FormData), scoped follow/флаги,
изолированный журнал лута по подземелью и карте. Нужен первый тест штатного призыва;
автоматическое монтирование чужой генерации и фактическая идентификация слоя ещё не готовы.
Подробности — [T18](fixes/T18-chalice-coop.md). Пользователь создаст чашу сам на текущих
`testHost/test`, без отката сейвов.

## Чаши: целевой объём

Уже есть `/channel/upload`, share, поиск по глифу и серверные записи;
`FIXED_CHALICES` содержит десять фиксированных подземелий. Произвольный поиск
ограничен намеренно, чтобы не подменять созданную чашу чужой. Это проверено по
исходнику `server/gameserver/bbsc_gameserver.py`, не новым тестом VPS.
Снятие кооп-стен опирается на данные игры, включая чаши; старое «список пуст» устарело.

Ограничения текущей основы: карты области 29 повторно используются разными
подземельями; область исключена из Shared Progress, а обычная синхронизация флагов
не даёт готового механизма для чаш. В guest-talk фильтре область 29 также закрыта.
Снять исключения целиком нельзя: можно перенести двери/боссов чужого подземелья в своё.

1. **Зафиксировать базу:** на тестовых сейвах создать фиксированную Птумеру;
   проверить канал/глиф, один и тот же dungeon у обоих, штатный призыв на первом слое.
2. **Определить ключ состояния:** канал/глиф + параметры генерации + слой;
   карта сама по себе не идентификатор подземелья. Определить, как гость получает
   то же подземелье при переходе хоста из Сна, и безопасный отказ при несовпадении.
3. **Один полный маршрут:** ритуал → вход → призыв → рычаг/дверь → босс →
   следующий слой → вайп → возврат в Сон → повторный вход без лишнего призыва,
   где это допускает реализованная бесшовная сессия. Уточнить недостающие механизмы по трассе.
4. **Изоляция и сохранение:** два разных dungeon с одинаковой картой, Shared Progress
   ON/OFF, свой лут/материалы/награды, меню/краш/повторный призыв. Своя чаша гостя
   сохраняет свои двери, боссов и слои. Сначала определить политику прогресса внутри
   одного общего dungeon; не приравнивать её к OR-слиянию обычных карт.
5. **Расширить покрытие:** корневые/генерируемые чаши, дополнительные обряды,
   разные доступы/материалы, три игрока. Общий поиск не включать без проверки,
   что он не подменяет текущую генерацию игрока.

Готовность этапа: двое проходят несколько слоёв одной фиксированной и одной
корневой чаши, переживают вайп/повторный вход, сохраняют награды; отдельная чаша
гостя не меняется. Затем контроль третьего игрока и других типов чаш.

## До публичной беты

Сохраняется ранее выбранный объём: основной кооп, Сон, DLC и чаши.
Shared Progress и recovery уже реализованы раньше старого деления beta 1 / beta 2;
не откладывать проверку сохранений как якобы будущую функцию.
Далее: стабильность GPU после переустановки своей сборки, контроль критических
исправлений, три игрока и длительный прогон, чистая установка/обновление/восстановление,
проверка источников и воспроизводимого пакета. Исторический [DISTRIBUTION](DISTRIBUTION.md)
не является текущим списком невыполненных задач: VPS, лаунчер и упаковка сервера уже существуют.
Сетевые сообщения/призраки/кровавые пятна не добавляются в обязательный объём этой ревизией.
Хост-миграция не планируется. Донаты — после открытой беты, как было решено ранее.
